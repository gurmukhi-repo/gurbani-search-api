# Contributing

Thank you for looking. A few things will save you time.

## What this is, and is not

This is a **search microservice** over a fixed corpus. It is not a reader
interface, not an LLM answering service, and not an authority on the text.

**Corrections to the scripture or to a translation cannot be fixed here.** The
text comes from [BaniDB](https://banidb.com); report it there and it will reach
this project on the next data release. Please open an issue here anyway if you
spot one, so it can be tracked — just expect it to be routed upstream.

## Setting up

```bash
npm install
npm run doctor     # says what this machine can run, and how to get further
npm test
```

Node 22 or newer. No build step, no toolchain, no Docker required.

## The three test tiers

**The rule: `npm test` passes on a clean clone with no data.** That is the job CI
requires, and it exists so you never have to download 270 MB to send a patch.

| Tier | Needs | Covers |
|---|---|---|
| **1** | nothing | routing, parameter bounds, error codes, fusion and `votes`, the pure Gurmukhi/keyboard/vector modules, the auth gate, the downloader. Runs against small synthetic fixtures in `test/fixtures/`. |
| **2** | `npm run fetch-data -- --core-only` (46 MB) | the real index: determinism across reloads, JS/Python parity, latency and size budgets, the full API end-to-end |
| **3** | `npm run fetch-data` (127 MB) | translations, the Darpan block, multi-index fusion |

Tier-1 fixtures are generated by `test/fixtures/build-fixtures.mjs` from a fixed
seed, with no model and no corpus. Their *rankings are meaningless* and no test
asserts on them — they exist so that everything around the ranking can be tested.

## Things that would genuinely help

Roughly in order of how much difference they would make:

1. **An optional rate limiter**, off by default. There is none on the search
   endpoints today.
2. **Client libraries** — Python, Go, a typed JS wrapper.
3. **More `deploy/` recipes** for hosts that are not already covered.
4. **Hybrid retrieval.** Dense search drifts on specific terminology; a BM25
   component over `gurbani.sqlite` would help and the data is already there.
5. **Another index** — a different script or language, built to
   [docs/index-format.md](docs/index-format.md).
6. **Documentation**, including translating the README into Punjabi.

## What will get a patch turned down

Better to say these up front than in review:

- A **network call at runtime**. The service dials out nowhere, and that is a
  feature, not an oversight.
- A **new runtime dependency** without discussing it first. `onnxruntime-node`
  is the only heavy one and it is staying that way.
- **Any binary or data file committed to git.** Data lives in releases.
- Anything that presents **machine-translated text as a human translation**, or
  that would surface Sahib Singh's ਨੋਟ side notes. See [NOTICE.md](NOTICE.md);
  these are correctness rules, not preferences.
- A **reader UI**. Out of scope for this repository.

## Style

Match what is there. Comments explain *why*, and cite a measurement when the
decision rested on one. There is no enforced formatter beyond `.editorconfig`.

Sign your commits off with `git commit -s` (DCO). There is no CLA: the code is
MIT, you keep your copyright, and a CLA would be friction for no benefit at this
size.

## A note on where this code lives

Most of this repository — the whole engine under `packages/`, `registry.js`, the
tests — is kept **byte-identical** with the private project it was extracted
from, at the same paths, so a patch here applies cleanly there. If you are
wondering why the layout looks like a monorepo with one app in it, that is why.
Please do not move files around without raising it first; it is load-bearing.
